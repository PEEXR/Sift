### Behaviour (decided with the user)
- The Review tab (third tab) shows the swipe screen. With nothing selected it shows a **picker**: header "Review", the search pill "Find screenshots to clean up", and a vertical list of the user's collections (compact tonal rows: colour dot/container from `collectionColors`, name, "N to review" pill using `CollectionSummary.reviewCount`, tap -> collection mode). Empty states: no collections -> "Create a collection first, then review what Sift put in it" with a button that switches to the Collections tab; no search query and every collection has 0 to review -> "All caught up".
- **Collection mode** (picked from the list OR opened from a collection page via "Review N unsure"): stack = `repository.getReviewQueue(collectionId)` (least confident first). Swipe right / lime keep button = `keepInCollection` (MANUAL). Swipe left / coral X button = `removeFromCollection` (EXCLUDED, remembered). A separate outlined "Delete file" button under the stack = delete the current file from storage (system delete request for that one file; on success remove the card, no undo). Never a swipe. Done card: "<Collection name> sorted!" with kept / removed / deleted counts and a "Back to collections" button.
- **Search mode** (user submitted a search in the pill; collection mode is cleared): stack = `repository.hybridSearch(query, limit = 60)` mapped to `ScreenshotItem`s, shown WEAKEST match first. Split via pure function `splitSearchResults(results: List<ScreenshotItem> /* best first */): SearchStack` where the best 40% (rounded up, min 1 when non-empty) are "strong matches" and the rest are "unsure"; the swipe stack is the unsure ones weakest-first, then the strong ones weakest-first. Swipe right / lime = keep (do nothing). Swipe left / coral trash = MARK for deletion (in-memory set only, no file touched yet). When the unsure cards are used up and only strong ones remain, show a pill button "Mark remaining N strong matches" (marks all of them, ends the stack). Summary card: "Delete N files?" + total size (`formatBytes` from `ui/collections`) + one coral button "Delete N files · X MB" -> a single `repository.createDeletePendingIntent(uris)` launched with `StartIntentSenderForResult`; on RESULT_OK `repository.removeDeletedScreenshots(ids)` and show a "X MB freed!" card; "Review again" restarts the search stack. Cancelling the system dialog returns to the summary card. A "Keep all" secondary button on the summary card clears the marks. Zero marked -> "Nothing marked" card.
- Search runs on submit (IME Search action), not per keystroke. Clearing the search returns to the picker (or the previous collection mode if it was opened from a collection). While searching show an expressive `LoadingIndicator` (`@OptIn(ExperimentalMaterial3ExpressiveApi::class)`). No results: "No matches. Try different words."
- Suggestion chips under the pill, only in picker/empty search: static list "Old screenshots", "Receipts", "Memes", "Notes" — hmm, the user has no default collections, so make them generic search prompts: "blurry screenshots", "chat conversations", "receipts and bills", "memes" — tapping runs that search.
- Tapping the top card (not dragging) opens the in-app viewer (`onOpenScreenshot`), same lambda the Library uses.

### Swipe card physics (match spec + mock)
- Top card follows the finger (horizontal, with slight vertical follow), rotates `dx / 16` degrees, KEEP (lime) / REMOVE or DELETE (coral) stamp fades in with `abs(dx) / threshold`; the whole screen background floods lime/coral proportionally (use `keepAccent`/`removeAccent` from `SiftTheme.extended`, low alpha, over `colorScheme.background`). Commit when `abs(dx) > 110.dp` or fling velocity is high; otherwise spring back (`spring(dampingRatio = DampingRatioMediumBouncy)`). On commit the card flies off-screen (animate offset), then the stack advances. Two cards peek behind (scale 0.95 / 0.90, y offset 18 / 36 dp, slight alternating rotation) and animate up as the top card leaves. Haptic tick on commit (`LocalHapticFeedback`, `HapticFeedbackType.LongPress` or `TextHandleMove`). Use `Animatable` + `pointerInput { detectDragGestures }`; hoist nothing animatable out of the card composable. Card content: the screenshot (Coil, `ContentScale.Crop`, large `shapes.extraLarge` radius, `surfaceContainer` placeholder), below it the date ("MMMM d") in the display font and a pill "N% sure" in collection mode (`score`-derived: use `((1f - score.coerceIn(0f,1f)) * 100)`-style mapping ONLY if the score semantic makes sense — read `CollectionMatcher.kt`/`replaceAutoMembers` to see what `score` stores (z-score? similarity?) and show "Unsure" instead of a fake percentage if it is not a probability), or "Weak match"/"Strong match" in search mode.
- Bottom controls row: big coral X (80 dp) / trash (search mode) on the left, "Undo" circle (48 dp, enabled only when there is something to undo) in the middle, big lime check (80 dp) on the right. Button taps animate the same fly-off as a swipe. Semantics: every control has a content description; swipe actions always have these button equivalents; contrast >= 4.5:1.
- **Undo** after every action, including a Snackbar-style "Removed from Memes · Undo" row (use a `SnackbarHost` lifted above the nav; or just the undo button + counts if simpler) — undo pops the last action off a stack: collection mode reverts the DB row (keep/remove -> restore the previous membership: re-upsert as AUTO with the previous score via a new repository method `restoreAutoMembership(screenshotId, collectionId, score)`; if the membership did not exist before, delete it with the existing DAO `removeFromCollection`), search mode just unmarks. Deleted-file actions are not undoable.
- Progress label ("12 of 40") + thick 14 dp rounded progress bar under the header, as in the mock.
